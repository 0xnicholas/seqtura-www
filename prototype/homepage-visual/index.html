工作方法论

从业务结果出发，
而不是从技术方案出发。

8 个交付阶段，4 组推进。Define / Validate / Deploy 不可跳过；每个阶段都有产出物和过关条件。

每个阶段都有可检查的产出物。

先把问题定义清楚，再定验收标准与评测集，然后才进入构建。Agent 不是一次模型调用，而是一条有状态的执行链；每一环都要能被验证、被审计、被接手。

  • ✓问题定义：值得做、不值得做，或先做哪一步，给出结论。
  • ✓验收标准：Define 阶段前置，逐项可量化、可复核。
  • ✓评测集：Build 之前锁定，正常 / 边界 / 失败样本齐全。
  • ✓生产上线：权限、监控、告警与回滚配置完成才算交付。

8 STAGES · 3 GATES 结构示意，非客户项目数据

Discover / Diagnose

先把业务、组织、系统、数据与约束盘点清楚，再判断值不值得做。问题定义不是需求清单，而是带 ROI 假设、可行性与风险的结论。

  • ✓客户业务画像
  • ✓问题定义与 ROI 假设
看阶段 01–02

Define / Design

先把验收标准与评测集定下来，再动手构建。Agent 规格卡写清职责、目标、非目标、权限与成功指标；方案架构写到可施工。

  • ✓Agent 规格卡与验收标准
  • ✓评测集 v0 与方案架构
看阶段 03–04

Build / Validate

在沙箱或预发环境跑真实任务，按规格构建可运行原型；再用同一套锁定评测集与验收标准逐项打分，产出可复核的评测报告。

  • ✓可运行原型
  • ✓评测报告与失败案例
看阶段 05–06

Deploy / Optimize

接入生产系统，完成权限、监控、告警与回滚配置；上线后用使用数据、失败案例与成本持续迭代 Agent、Skills、Knowledge 与 Workflow。

  • ✓生产 Agent 与上线检查清单
  • ✓运营报告与下一轮迭代计划

一条任务，从进入到留下什么。

00:00task.in来自客户系统的退款咨询
00:03policy.check身份与权限校验通过
00:11tool.call查询订单与售后记录
00:42hitl.gate金额超过阈值，等待业务负责人审批
01:06eval.run按评测集检查回复与工具调用
01:08task.out输出回复，写入审计字段

每一步都有输入、输出、权限与评测记录。 不是一段黑盒回答，而是一条可回放、可审计的执行链。

C1 / IDENTITY

身份与权限

每个 Agent 动作都有主体、权限和审批记录。读、写、外发分开授权，敏感操作必须经过 HITL gate。
